III — Работы

01
Production-Ready · RAG & Agents
Корпоративный FAQ-LLM-ассистент

Production-ready RAG-система с детерминированным LangGraph-агентом и гибридным поиском, обеспечившая 100% точность на 211 вопросах.
  • Методы: Markdown-aware чанкинг, эмбеддинги bge-m3, Reciprocal Rank Fusion (RRF), few-shot промптинг и LLM-as-a-Judge.
  • Результат: Наивный RAG (35% точности) заменен на гибридный поиск, что дало 100% точности (Hit Rate@5 = 1.0, MRR = 1.0) на датасете из 211 вопросов.
  • Архитектура: Детерминированный FSM-роутер на LangGraph с паттерном short-circuiting (снижение latency на 70% для chitchat/out-of-scope запросов).
  • Надежность: Паттерн Defensive Programming (format="json" + Pydantic V2 + json_repair + Retry with Feedback) для 100% валидности вывода.
  • LLMOps&DevOps: Waterfall-анализ задержек через Langfuse, graceful degradation при сбоях, упаковка в Docker (multi-stage build).
# LangGraph: детерминированный FSM-роутинг с short-circuiting
def route_decision(state: AgentState) -> str:
  intent = state["intent"]
  if intent == "faq": return "retrieve"   # Полный RAG-цикл
  if intent == "chitchat": return "chitchat" # Short-circuit (быстрый ответ)
  return "fallback"                # Защита от галлюцинаций

02
Enterprise RAG · Legal Tech · Python
RAG-анализатор юридических договоров (Contract Analyzer V2)

Модернизация RAG-пайплайна: рост Context Recall на 310% и Faithfulness на 68% за счет гибридного поиска, переформулирования запросов и строгой валидации вывода без тяжелых фреймворков.
  • Проблема: Базовый RAG давал Recall 0.19 и Faithfulness 0.47 из-за лексического разрыва, галлюцинаций модели и сломанной фильтрации по метаданным (конфликт кириллицы в запросе и латиницы в именах файлов).
  • Результат: Честный рост метрик на кастомном Ground Truth датасете: Context Recall 0.19 → 0.67, Faithfulness 0.47 → 0.67. Время анализа документов сократилось с часов до минут.
  • Качество: Написал кастомного LLM-as-a-Judge с Chain of Thought и явной рубрикой, что устранило проблему Prompt Anchoring (бинарного смещения оценок модели).
  • Архитектура: Внедрил 4-х ступенчатый поиск: Query Rewriting (LLM-синонимы), специализированные эмбеддинги (multilingual-e5-small), Weighted Hybrid Search (FAISS + BM25 + RRF с весами 1.0/0.3) и Cross-Encoder реранкинг.
  • Надежность: Реализовал кросс-языковой Fuzzy Matching (unidecode + thefuzz) для точной фильтрации документов и алгоритмическую Self-Correction (проверка чисел из ответа на наличие в исходном контексте).
# Self-Correction: алгоритмическая валидация фактов перед отдачей ответа
def validate_grounding(answer: str, context: str) -> str:
  numbers = re.findall(r'\d+(?:\.\d+)?%?', answer)
  if any(num not in context for num in numbers):
    return answer + "\n\n[⚠️ ВНИМАНИЕ: Обнаружены числа, отсутствующие в контексте.]"
  return answer

03
AI Product · HR Tech · Next.js
HR-система онбординга и адаптации сотрудников

Платформа адаптации новичков с AI-ассистентом на базе RAG: три роли, персональные маршруты онбординга, геймификация и аналитика рисков — от дашборда сотрудника до governance-очередей администратора.
  • AI-ассистент (RAG): чат-бот отвечает на вопросы новичков по базе знаний с указанием источников; конфиденциальные запросы (hrbp, confidential, private) фильтруются и эскалируются без утечки контента.
  • AI-интерпретация попыток: автоматическая проверка выполнения задач сотрудником — вердикт ACHIEVED / NOT_ACHIEVED / AMBIGUOUS с confidence %, при этом кадровое решение всегда остаётся за руководителем.
  • Три роли + governance: Сотрудник (прогресс-кольцо, learning path, streak-геймификация), Руководитель (risk heatmap, pulse sentiment, AI-рекомендации), Администратор (CRUD мастер-данных, согласования, diff-preview, аудит-журнал).
  • Приватность по дизайну: voluntary-поля профиля с метками видимости (Only me / HR / HR+Manager), private-запросы к HRBP невидимые менеджеру, отложенная публикация обратной связи (2 часа на корректировку).
  • Демо-панель презентера: переключение сценариев (critical / tails / t-5 / transfer-pending) в реальном времени, ползунок дня 0–90, toggle AI/HRBP с fallback-поведением, сброс состояния в localStorage.
